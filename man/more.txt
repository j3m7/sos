NAME
    more - read a file a screen at a time, whatever its size

SYNOPSIS
    more <file>
    <command> | more

DESCRIPTION
    Shows the file a screen at a time, on the same kind of terminal as 'edit'
    and with the same screen size handling (Ctrl-L after resizing). The file
    can be of any size: only a 16 KB window of it is in memory, read from the
    card as you move. Nothing in a file can send the terminal a sequence:
    controls, invalid UTF-8 and invisible or bidi characters show as '?', and
    long lines scroll sideways.

    Piped, 'more <file>' prints the file as plain text, as 'cat <file>' does,
    instead of opening the pager: 'more /log/sos.log | tail 5'.

    The bottom row shows the file name, the lines on screen ('lines 12-34',
    with the total once it is known: after G, or once the end has been on
    screen) and how far in you are, or END.

    A search brings the line with the match to the top (near the end, the
    last screen is shown instead), shows every match on screen in reverse
    video, and says on the bottom row which line the match is on ('found on
    line 42'), so a match on a page that fits the screen is shown too.

KEYS
    Space, f, PgDn / b, PgUp    a screen forward / back
    d / u                       half a screen forward / back
    j, Enter, Down / k, Up      a line forward / back
    g, Home / G, End            the start / the end of the file (the first G
                                on a large file counts its lines, about a
                                second per megabyte)
    Left / Right                half a screen sideways, for long lines
    / (Ctrl-F)                  find: type the text, Enter finds the first
                                match from the top line on (empty: the last
                                search again), wrapping around to the start;
                                Ctrl-C cancels. Text with no capital letter
                                ignores case ('/error' finds Error and
                                ERROR); with one it must match exactly
    n                           the next match: after the one before while
                                that is on screen, else from the top line
    F                           follow: stay on the end as output arrives
                                ('<command> | more' while the command runs;
                                any movement key leaves it)
    Ctrl-L                      redraw, and ask the terminal for its size
    h, ?                        list the keys
    q (Ctrl-Q, Ctrl-C)          quit (Ctrl-C first stops a command that is
                                still running: see NOTES)

NOTES
    '<command> | more' runs the command with its output kept instead of
    printed, and shows it here ('dmesg | more', 'ls | more', 'wifi stats chip
    | more'). A command that runs for a while ('cat big.log | more', 'ping
    host | more') is shown as soon as it has printed something, and its output
    keeps arriving while you read: the bottom row shows '...' for the total
    and 'END so far' at its end until the command has finished, and F follows
    the end. While it runs, q ends the command and leaves, and Ctrl-C stops
    it and keeps what it printed ('stopped' in the bottom row; Ctrl-C again,
    or q, leaves). Up to 32 KB of output is kept; then the command is
    stopped and the text ends with a note saying so. A command that asks a
    question runs as if there were no '| more' (if it asks while being
    shown, the pager leaves and its output so far is printed above the
    question), and a full-screen program (edit, more, man) ignores it.
    Ctrl-C before the command has printed anything drops it, as does
    anything typed before the pager opens (it would be keys for the pager).
    A command with no output says so instead of opening the pager. Messages
    from other shells wait until the pager is left.

PIPES
    A command's output can go through filters on its way to the screen or to
    the pager, one after another, each after a '|':

        dmesg | grep wifi
        cat /log/sos.log | grep -i error | tail 20 | more
        help | wc

    The filters are grep (lines with a text), head (the first lines; it
    stops the command once it has them), tail (the last lines) and wc
    (counts); see their pages. 'tee [-a] <path>' also writes what passes it
    to a file ('dmesg | tee /dmesg.txt | more'). 'more' can only come last,
    and at most four filters fit in a line. The output streams through:
    grep shows lines as the command prints them, and with '| more' only what
    the filters let through is kept, so 'cat big.log | grep error | more'
    isn't cut at 32 KB unless the matches are. When the 32 KB are full the
    command is stopped,
    as head stops it.

    A '|' is always a pipe, and the word after it must be a stage name
    (grep, head, tail, wc, tee, more): 'ls | morex' says "morex: not a
    filter" and runs nothing. A '|' that is text is quoted ('echo "a|b"';
    QUOTING in 'man intro'). A line may end with '> <path>' (or '>>'), which
    writes what the stages let through to the file instead of the screen, as
    a tee that passes nothing on ('man tee'); it can't go with '| more'. A
    stage that doesn't parse ('x | grep', 'x | head y') prints its usage and
    the command doesn't run. Ctrl-C drops
    what the filters hold (tail's lines, wc's count); a command that asks a
    question or draws its own screen runs as if there were no pipe. Tab
    completes the stage names after '| ', and grep's options.

    'man <topic>' shows a manual page in this viewer (piped, it prints the
    page as text, like 'more <file>'). Log messages are held on
    the console while it runs there, as for the editor.
