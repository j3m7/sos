NAME
    time - the clock, the RTC and time sync over NTS

SYNOPSIS
    time
    time sync
    time sync sntp                      (console only)
    time auto [<hours> | off]           (change: console only)
    time cal [<ppm> | off]              (change: console only)
    time server [<name> | default]      (change: console only)
    time zone [<name> | utc]            (change: console only)
    time zone list [<prefix>]
    time zone install

DESCRIPTION
    All times are UTC: the clock, the RTC, file times, logs. A time zone only
    adds a line of local time to 'time' (see TIME ZONES). The RTC (a PCF8523
    on the Adalogger, with its coin cell) is the source of truth: at boot the
    clock is set from it. Network time comes from NTS (Network Time Security,
    authenticated NTP): a TLS key exchange with the NTS server on port 4460,
    then NTP queries that only accept replies that check out under the
    server's key. There is no fallback to plain NTP: without NTS and without
    an RTC time, the clock stays unset.

    'time' shows the date and time and where it came from (RTC, NTS or SNTP),
    the RTC's reading and backup-battery state, the calibration, the last sync
    with its correction and round trip, a failed attempt and when it is
    retried, the server and the periodic setting.

    'time sync' syncs the clock and the RTC from NTS now. The board also syncs
    by itself when the RTC has no valid time (retrying with doubling delays),
    and periodically if 'time auto <hours>' (1 to 720; default off) is set:
    one interval after the last successful sync, or after boot if there has
    been none. A correction of more than 5 minutes is logged as a warning.
    'time sync sntp' does one plain, unauthenticated SNTP sync on request.

    'time server <name>' sets the NTS server (host name or IPv4 address);
    'default' goes back to the build-time one (time.cloudflare.com). Its
    certificate must chain to a trusted root ('tls roots').

    'time cal <ppm>' corrects the RTC's rate. To measure: 'time sync', leave
    the board for a day or more, restart it and 'time sync' again; 'time'
    shows the step, e.g. 'clock stepped -5419 ms' (negative: the RTC ran
    fast). ppm = milliseconds stepped / seconds waited x 1000, positive if
    fast: 5419 ms in 59051 s is 92 ppm, so 'time cal 92'. The RTC is slowed or
    sped up by the nearest step of 4.34 ppm and 'time' shows the rate applied
    ('cal: slowed by 91.1 ppm'). The value replaces the previous one: after
    measuring again, give the rate shown plus the new error. 'time cal off'
    removes it. Saved, and written into the RTC at boot if the chip doesn't
    have it.

TIME ZONES
    'time zone <name>' sets the zone 'time' shows local time in, by its IANA
    name (Europe/Madrid, America/New_York; case doesn't matter, and a space
    may stand for '_'). The name is looked up in /tz/zones.bundle on the
    card, and the name and the zone's rule (a POSIX TZ string such as
    CET-1CEST,M3.5.0,M10.5.0/3) are saved, so local time shows with the card
    out too. A name that isn't found gets the closest ones. 'time zone utc'
    clears it. Then 'time' adds a line:

        local:  2026-11-27 14:03:05 CET (UTC+01:00, Europe/Madrid)

    'time zone' shows the zone, its rule, local time, and the tzdata release
    of the card's bundle; if the card's rule for the zone differs from the
    saved one, it says so, and 'time zone <name>' again takes the card's.

    'time zone list' lists the zones on the card with their rules, those
    starting with <prefix> if one is given; 'time zone list europe/ | more'
    pages them.

    'time zone install' downloads tz/zones.bundle from the main branch of
    the SOS repository on GitHub into /tz (the board needs the network),
    checks every line of it, and says whether the saved zone's rule changed.
    It works from any shell, SSH included, on purpose: the card can be
    written over SFTP anyway, and only 'time zone <name>' on the console
    changes the setting. From a computer, tools/tz-install.sh <host> copies
    it over SFTP. The bundle is built from IANA's signed tzdata releases.

    Only what is shown changes. Log files, file times (ls, SFTP), chat and
    wall stamps and log rotation stay UTC and say so.
